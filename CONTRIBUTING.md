# Contributing to CISSP Zero to Hero

Thank you for helping improve the CISSP Zero to Hero knowledge base.

This repository is intended to provide clear, practical, and exam-focused cybersecurity knowledge for CISSP candidates. Contributions are welcome, especially when they improve accuracy, clarity, completeness, or the learning experience.

## What You Can Contribute

You can contribute by:

* Correcting factual, technical, or grammatical errors.
* Improving explanations that are unclear or difficult to understand.
* Adding useful cybersecurity examples or real-world scenarios.
* Identifying outdated information or references.
* Suggesting missing CISSP concepts or important topics.
* Improving diagrams, terminology, and learning resources.
* Suggesting improvements to the structure or organization of the knowledge base.

## CISSP Quality Standard

Contributions should follow the CISSP mindset.

Content should be:

* Accurate and technically sound.
* Clear and understandable.
* Relevant to information security management and governance.
* Focused on risk, business impact, and security objectives where appropriate.
* Useful for understanding concepts rather than simply memorizing definitions.
* Consistent with established cybersecurity frameworks, standards, and terminology.

When a topic has multiple valid approaches, explain the context rather than presenting one approach as universally correct.

## Before Contributing

Before submitting a change, please check whether the topic already exists and make sure your contribution does not unnecessarily duplicate existing content.

When correcting technical information, provide a reliable reference whenever possible, especially for changes involving standards, frameworks, regulations, or security terminology.

## How to Contribute

The preferred workflow is:

1. Identify the page or topic you want to improve.
2. Create an issue or discussion describing the proposed change, when appropriate.
3. Create a branch containing your changes.
4. Make the smallest practical change needed.
5. Review your changes for accuracy, clarity, spelling, and formatting.
6. Submit a Pull Request explaining what you changed and why.
7. The contribution will be reviewed before being incorporated into the main knowledge base.

For small corrections, a direct Pull Request may be sufficient.

## Pull Request Guidelines

Please keep Pull Requests focused.

A good Pull Request should explain:

**What changed?**
Briefly describe the modification.

**Why was it changed?**
Explain the problem or improvement.

**What is the source?**
Provide references when the change is based on a standard, framework, regulation, publication, or other authoritative source.

Avoid combining unrelated changes in the same Pull Request.

## Sources and References

For cybersecurity concepts, prefer authoritative sources such as:

* NIST publications
* ISO/IEC standards
* CISA guidance
* ENISA publications
* OWASP resources
* Official regulatory or government sources
* Relevant vendor documentation for technology-specific information

Community contributions and professional experience are welcome, but factual claims should be supported by appropriate sources whenever practical.

## Important: CISSP Exam Perspective

This knowledge base is designed to help candidates develop security judgment, not simply memorize isolated facts.

When contributing exam-oriented content, avoid wording that suggests that a single technical solution is always correct.

CISSP questions often depend on context, organizational responsibilities, risk, business objectives, and the meaning of words such as **FIRST**, **BEST**, **MOST**, and **PRIMARY**.

If a concept has an important exam nuance, explain it.

## Questions and Suggestions

If you are unsure whether something belongs in the knowledge base, open an issue and explain your idea.

Good contributions do not need to be large.

A small correction that makes a concept more accurate can be more valuable than a large amount of new content.

## Thank You

Every correction, suggestion, reference, and improvement helps make this knowledge base more useful for the CISSP community.

**Learn the concept. Understand the risk. Think like a security manager.**
